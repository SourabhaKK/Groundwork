# Tech Stack — Locked

This stack is locked before implementation begins. Any change during the build must be logged in `workflows.md` as a deviation with a reason — no silent substitutions.

| Layer | Choice | Why (vs. main alternative considered) |
|---|---|---|
| Language | Python 3.11+ | Matches candidate's existing production ML/LLM stack (FinSight, SecureOps); no reason to introduce a new language under a 6-day deadline. |
| Agent orchestration | **LangGraph** | Rejected: plain sequential prompt-chaining (LangChain-style linear chain). LangGraph's explicit state graph makes routing decisions, stopping conditions, and failure branches inspectable and testable — directly serves the brief's "Agent design" grading criterion. Candidate has solo production LangGraph experience (SecureOps), so this is a real strength to demonstrate, not a new risk. |
| Company resolution & structured data | **Companies House REST API** (official, free) | Required by the brief. No alternative considered — this is the canonical source of truth for UK company identity, officers, filing history, SIC codes. |
| Web/news/review research | **Tavily Search API** | Rejected: raw scraping via requests/BeautifulSoup (extra scraper/parser to build and defend, no upside). Rejected: SerpAPI/raw search APIs (return only links + snippets, no content extraction — would still need a scraping step after). Rejected: Exa (comparable, lateral alternative — not worse, just not chosen). Rejected: Claude's native web search tool (search and reasoning get entangled in a single LLM call — harder to log/audit as a discrete, independently-retryable pipeline step, which matters directly for the brief's "Agent design" criterion: clear reasoning about *when to stop gathering* is much easier to demonstrate when search is its own visible LangGraph node). Tavily returns cleaned, source-attributed content in one call, maps directly onto the `EvidenceClaim` schema, and its free tier (1,000 credits/month, no card) comfortably covers an evaluation demo's realistic usage (~250-400 full report runs before any ceiling). |
| LLM provider — primary | **Claude (Anthropic API)**, via `anthropic` SDK — **tiered by task**: Haiku for extraction (high-volume, low-reasoning), **Sonnet reserved for synthesis only** (business model / competitive landscape / quality-signals generation, ~3-4 calls per run) | Tiering by task complexity balances cost against quality where quality is actually visible to the grader — synthesis is the one step where a weaker model's shallower reasoning would show up directly in the deliverable (risking "Product thinking" and "Data grounding" criteria), so it gets the stronger model; extraction doesn't need it. Also a deliberate signal: Allica's own recruiter flagged Claude Code as core to their engineering culture — using Claude natively inside the agent, not just as a coding tool, reinforces that. |
| LLM provider — fallback | **Gemini 2.5 Flash (free tier), thinking disabled**, auto-switched via circuit breaker — *was 2.0 Flash; changed in Phase 3, see `workflows.md` deviation log* | Rejected: a second paid provider (unnecessary cost given Sonnet usage is already minimal). Fallback triggers only on Anthropic failure/rate-limit — same circuit-breaker pattern (N consecutive failures → cooldown → reroute → retry primary after cooldown) as the SecureOps hackathon's provider-fallback router, reused as a pattern, not copied code, and disclosed as such. Protects both the demo's uptime for evaluators and the candidate's own API cost exposure, since the hosted demo runs on the candidate's personal key. |
| Structured output / validation | **Pydantic v2** | Consistent with FinSight's schema approach; enforces that every extracted claim carries a typed source field — this is the mechanism, not just a convention, that makes grounding auditable. |
| Backend / API | **FastAPI** | Consistent with candidate's existing deployment repo and with Allica's own production stack; async-native, pairs naturally with LangGraph's async execution, gives a clean `/report` endpoint to demo against. |
| Frontend | **Minimal Streamlit app** (single page: input box, report render) | Rejected: React/Next.js frontend. Brief explicitly deprioritises UI polish ("don't spend time on visual polish"); Streamlit gets a usable demo UI in under an hour, freeing the 6-day budget for agent quality instead. |
| Access control | **Token-gated demo endpoint** | The hosted demo runs on the candidate's personal API key(s); a fully open public URL risks unbounded cost from bots or repeated evaluator testing. A shared access token (given to Allica directly, e.g. in the README/submission email) plus per-IP/global rate limiting on `/report` keeps cost bounded without meaningfully restricting the evaluator's ability to test it. Rejected: fully open URL (matches the brief's literal wording most simply, but leaves cost exposure uncapped for an unknown review-window duration). |
| **Hosting / demo — LOCKED** | **Google Cloud Run** | Rejected: Render (genuine free tier, but spins down after inactivity — 30-60s cold start on the *first* request an evaluator makes, which is the worst possible moment for a slow response). Rejected: Fly.io (no longer offers a free tier for new accounts as of 2026 — requires payment regardless). Rejected: Vercel (serverless execution timeout — 10s on the free Hobby tier — is incompatible with a multi-step LangGraph agent run that can take 30-90+ seconds; a hard architectural mismatch, not a style preference). Cloud Run's Always Free tier (2,000,000 requests, 180,000 vCPU-seconds, 360,000 GiB-seconds per month, per billing account, never expires) is orders of magnitude beyond what a single-reviewer evaluation demo will use. Requires a card on file for identity verification, but nothing is charged within these limits — candidate has confirmed this tradeoff is acceptable. Container-based (Docker), a natural, production-credible fit for FastAPI specifically, which is worth having on the README given Allica's own stack runs FastAPI extensively. |
| Testing | **pytest**, with LLM calls mocked in unit tests | Consistent with candidate's existing testing philosophy across all 7 portfolio projects — deterministic, fast tests for logic; a small number of real end-to-end runs (not part of CI) for actual grounding verification. |
| Dependency management | **`pyproject.toml` + `uv` or `pip-tools`** | Reproducible installs, consistent with the deployment repo's existing practice. |

## Explicitly Rejected for This Project

- **No vector database** (Qdrant, etc.) — corpus per run is small and ephemeral (one company's worth of live-fetched documents), not a persistent large corpus like FinSight's SEC filings. A vector store would be over-engineering here; in-context retrieval over the current run's gathered documents is sufficient and simpler to audit.
- **No fine-tuning** — see PRD §6.
- **No separate frontend framework** — see row above.
- **No fully-open (ungated) public demo URL** — see Access Control row above.
- **No Render/Fly.io/Vercel for hosting** — see Hosting row above for the specific reason each was rejected.

## Final Locked Stack Summary (as of this revision)

Orchestration: LangGraph · Company data: Companies House API · Web/news/reviews: Tavily · LLM primary: Claude (Haiku extraction, Sonnet synthesis-only) · LLM fallback: Gemini 2.5 Flash, thinking disabled (auto-switched) · Backend: FastAPI · Frontend: Streamlit · Access: token-gated · Hosting: Google Cloud Run.
